# Прогресс Chertilla

Текущая версия: `0.1.10.0005` (обновлено 2026-11-04).

## Сделано
- **Шаги 1–10:** холст на Skia, пан и зум, сетка и оси, инструменты (точка, отрезок, окружность, бесконечная прямая), ввод пальцем и через окно координат, привязка с лупой (долгое нажатие), история «Отменить / Вернуть», сохранение и загрузка проектов (JSON), список проектов, отладочный проект «Тест (Отладка)» на ~300 фигур.
- **Шаг 11 — оптимизация рендеринга** (версии 0.0.0.0013–0.0.0.0017):
  - фигуры рисуются в мм через одну матрицу Skia 3×3 на группе, пути не пересоздаются при пане/зуме;
  - толщины линий и размер точек делятся на масштаб, чтобы на экране оставаться постоянными;
  - сетка — одна «плитка», строится только при изменении размера холста;
  - отсечение невидимого (`getVisibleShapes`) по области покрытия (экран + 1 экран запаса);
  - лупа (второй экземпляр чертежа) рисуется только пока открыта;
  - защита от NaN / деления на 0 в матрице и толщинах, предохранитель в `gridStepMm`.
- Хотфикс зависания при входе в проект (0.0.0.0014): точная причина не найдена, добавлены защиты; повторно зависание не наблюдалось.
- Шаг 11 зафиксирован пользователем как рабочий результат.
- **Шаг 13 — монитор производительности** (0.0.0.0019): кнопка «PERF» в «Тест (Отладка)», панель с UI FPS, JS FPS и памятью JS (`src/components/PerfMonitor.tsx`).

- **Замер 0.0.0.0019** («Тест (Отладка)»): приближено — UI 60 / JS 60; отдалено (все 300 фигур) — UI 5 / JS 5, память стабильна.
- **Шаг 14 — сцена Skia Picture + LOD** (0.0.0.0020):
  - фигуры больше не собираются в один общий путь (вероятная причина 5 FPS), а пишутся в Skia Picture отдельными командами `drawCircle` / `drawLine` / `drawPoints`;
  - сцена перезаписывается только при смене покрытия (полэкрана / зум 2×), ступеньки масштаба (~19%) или списка фигур; при пане — никогда;
  - LOD при > 100 фигурах: окружности < 3 px и отрезки < 1 px — точками.

- **Шаг 15 — сетка через Picture + «быстрый жест»** (0.0.0.0021):

## Что стоит помнить
- Точность при экстремальном зуме (до 1000×) далеко от начала координат может слегка страдать: матрица Skia считается во float32.
- Babel не трогать: `babel-preset-expo` сам подключает плагин worklets.

- **Шаг 33 — облачная сборка APK** (0.1.2.0002): eas.json (профиль preview = APK), в app.json пакет com.chertilla.app, имя Chertilla. Папка android/ в .gitignore, поэтому EAS пересоздаёт её из app.json. Сборка не запускалась (нужен вход в Expo).

- **Шаг 34 — атомарное сохранение** (0.1.2.0003): JSON сначала пишется во временный файл, прежняя версия сохраняется в `.bak` до успешной замены; при ошибке или после сбоя восстанавливается целая версия. Внешний API хранения не изменён.

- **Шаг 35 — BBox-префильтр привязки** (0.1.2.0004): `findSnapPoint` отсекает далёкие фигуры по габаритам до расчёта характерных точек, пересечений и проекций. Бесконечные прямые всегда проходят фильтр; запас 0.001 мм сохраняет пограничные привязки. Внешний API привязки и рендеринг не изменены. TypeScript и ESLint — без ошибок.

- **Шаг 36 — автономный сбор крашей** (0.1.2.0005): фатальные JS-ошибки сохраняются в `last_crash.log` и отправляются в Telegram с троттлингом; при следующем запуске несданный отчёт можно повторно отправить или скопировать в кастомном модальном окне. В `app.json` добавлены заглушки конфигурации Telegram, `.env` исключён из Git.

- **Шаг 37 — скрытый тест краша** (0.1.2.0006): на главном экране долгое нажатие на серый номер версии вызывает тестовую фатальную JS-ошибку для проверки Telegram-логгера и модального окна. Обычное нажатие действий не выполняет.

- **Шаг 38 — брендинг, Splash и темная тема** (0.1.2.0007): название приложения исправлено на «Чертилла» (две «л»), `slug` — `chertilla`. Splash настроен на белом фоне с лаконичной надписью Chertilla (`assets/splash.png`), скрывается после инициализации приложения. Добавлены светлая и темная палитры UI, `ThemeProvider` с режимами `light` / `dark` / `system`; для Альфа-версии по умолчанию выбрана темная тема. Цвета холста и фигур Skia не изменялись.

- **Шаг 39 — команда «Разделить»** (0.1.3.0001): кнопка «Разделить», выбор отрезка / окружности / дуги и кастомное окно ввода целого N. `divideShape` равномерно строит N−1 внутренних точек на отрезке и дуге либо N точек на окружности, с округлением до 0.001 мм. Точки — обычные `PointShape`, добавляются одним шагом истории через `addShapes` и рисуются существующей сценой Skia.

Середина отрезка округляется до 0.001 мм и подсвечивается отдельным синим треугольником; тип привязки — `'midpoint'`.

- **Шаг 41 — перемещение и копирование фигур** (0.1.5.0001): единственную выделенную фигуру можно перетаскивать за линию.
